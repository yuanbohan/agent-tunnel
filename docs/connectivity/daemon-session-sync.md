# Daemon Session Sync Contract

## Status

This document captures the daemon-owned session metadata contract that replaces Relay-owned session discovery in the target connectivity architecture.

## Core Rule

In the target design, Relay knows which daemons are online. The daemon tells Android which sessions exist.

That means:

- no `GET /api/sessions` in the target design
- no Relay session index authority
- session metadata arrives only after secure daemon connectivity is established

## Delivery Split

The daemon-to-Android sync path is intentionally split into three layers:

1. session metadata
2. preview content
3. interactive terminal content

### Session Metadata

Delivered on the control stream through:

- `session_index`
- `session_upsert`
- `session_gone`

Purpose:

- tell Android which sessions currently exist on this daemon
- keep session rows renderable before preview arrives

### Preview Content

Delivered on the control stream through:

- `preview_snapshot`

Purpose:

- fill the list UI with lightweight current content
- avoid turning preview into terminal emulation
- deliver real content only for sessions whose active-session lease has been granted by Relay and accepted by the daemon

### Interactive Content

Delivered on per-session interactive streams through:

- `snapshot_begin`
- `snapshot_chunk`
- `snapshot_end`
- `live_bytes`

Purpose:

- support full terminal rendering only for sessions the app has attached interactively

## Session Metadata Fields

Phase-1 daemon-to-Android session metadata should include:

- `session_id`
- `label`
- `command_preview`
- `cwd`
- `git_branch`
- `started_at`
- `updated_at`
- `online`

This keeps the session list useful without putting session authority back into Relay.

## Preview Boundary

Preview text is not session metadata.

Preview is:

- sent separately
- generated by the daemon
- updated independently
- gated by active-session lease rather than by raw session existence

That separation lets Android render the session list progressively:

- daemon card first
- session metadata next
- preview later

## Bootstrap

After the QUIC transport is ready, the daemon sends:

1. `session_index`
2. zero or more `preview_snapshot`

The initial `session_index` must contain the full current session set for that daemon.

The intended bootstrap order is:

1. QUIC/TLS transport becomes ready
2. daemon sends `session_index`
3. daemon sends `preview_snapshot` only for sessions that currently have a valid active-session lease and preview text
4. Android renders list metadata first, then preview as it arrives

## Incremental Updates

After bootstrap, the daemon sends:

- `session_upsert`
- `session_gone`

Each `session_upsert` should carry the full current metadata object for that session rather than a patch.

## Sanitization

The daemon should treat these fields as display metadata:

- `label`
- `command_preview`
- `cwd`
- `git_branch`

That means:

- avoid dumping raw argv when a redacted command preview is better
- normalize paths for display
- keep line lengths bounded

This is still less sensitive than terminal payload, but the daemon should not be careless.

## Subscription Boundary

The daemon is not subscription-aware. It does not know whether the account is free or pro.

It only knows whether Android has presented a valid Relay-issued lease token for a specific session. That token decides whether the daemon may emit:

- `preview_snapshot`
- interactive attach grant
- terminal snapshot / live bytes

This keeps subscription enforcement at Relay while still making direct connections enforceable.
